Warsaw 2076 / Team onboarding02 / The idea

A route should fit your day.

Time. Interests. Errands.
The city around you.

The problem

People plan around several needs at once. A destination alone does not describe the trip.

Our response

Combine city data and personal preferences to suggest routes and useful stops.

Warsaw 2076

Make greener, quieter travel and local discovery easier through everyday decisions.

Warsaw 2076 / Team onboarding05 / Scope

The build we can finish.

Core

Map, preference input, route alternatives, place cards, clear data labels and one shared route service.

Agent access

Natural-language interpretation and explanation, then one Model Context Protocol (MCP) tool over the same service.

Stretch

Progressive web app (PWA), landmark models and an augmented reality (AR) concept mock-up.

Advertising, promotions, personal calendars, achievements and full multimodal travel stay in the future vision. User data stays on the device; the demo backend stores none.

  • OpenStreetMap places and parks

  • Street geometry from a checked routing provider

  • Route noise and air scores
  • Traffic, incidents and roadworks
  • Charging, events and personal profiles

Label each simulated input. Do not imply live measurements or availability.

Park proximity can be a documented proxy. Historical data is context, not a live street reading.

Integrate in the first two hours.

Warsaw 2076 / Team onboarding12 / Coding agents

Give each agent a bounded task.

A useful task brief

Issue and expected result
Allowed files
Shared contract
Checks to run
Reviewer and next handover

Your own workspace

Each person uses a separate checkout, branch and their own account. No shared mutable agent directory.

Short feedback loops

Escalate a blocker after 15 minutes. Sync as a team every 60–90 minutes.

GitHub holds task status. Your STATUS.md records only the current handover.
